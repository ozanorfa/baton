## 2026-07-12 · Session 2 — Session Chaining (ADR-015): the founding token-savings feature, finally shipped

- 👤 Two pointed questions: (1) is a live back-and-forth between stages (Coder asks Codex a question mid-task) possible? (2) tokens are still too high — the whole reason for building this was to save tokens, and it doesn't feel like it's happening.

## 2026-07-28 (cont.) · ADR-031 implemented — model choice offered at setup

- 🤖 Third queued ADR. `batonai init` now asks which model each provider should use and writes the answer into `.ai/config.yaml` as ordinary configuration. Verified live: answering `haiku` for claude and pressing Enter for codex produces `providers: {claude: {model: haiku}}`, and `batonai config show` reports `providers.claude.model = haiku` sourced from `project` while codex stays `—`/`defaults`.
- **Nothing changes for anyone who skips it.** Enter everywhere writes no `providers:` block at all, so the config is byte-identical to before; `--no-models` skips the question outright; and without a terminal on both ends it is never asked, so `batonai init` in a script cannot block.
- **Only asked when a config is actually being created.** `init` is idempotent and keeps existing files, so re-asking on a re-run would collect an answer it then silently discards — a test pins that a second `init` does not re-ask.
- **No validation, by design.** Model identifiers are vendor-specific and change often, so an unrecognised answer is passed straight through to the CLI, which is the authority; a test pins that `some-future-model-2029` survives into the config. `opus/sonnet/haiku` are offered as suggestions for claude only, with a one-line cost/speed hint.
- 🐛 Caught in live testing, not in the unit tests: the prompt label was built with Rich markup, but `typer.prompt` writes to the stream raw, so users saw a literal `[dim](opus/sonnet/haiku)[/dim]`. Fixed, and pinned by a test asserting no markup reaches a prompt label.
- 🤖 The wizard's call site now passes `init(models=True)` explicitly — Typer command defaults are `OptionInfo` objects, and the previous bare `init()` only worked because such an object happens to be truthy.
- ✅ **278 passed** (measured), ruff clean.

## 2026-07-28 (cont.) · ADR-030 implemented — live progress notes (codex)

- 🤖 Last queued ADR, and the largest. `Transport.run` gains an optional `on_line` sink; **without it the original single `subprocess.run` call is taken byte for byte**, so the well-understood buffered path carries zero risk from this change. With a sink, `_run_streaming` uses `Popen` with stdin written on one thread and stderr drained on another — a large prompt can fill the pipe buffer before the child reads, and a chatty child must not block on a full stderr pipe while we wait on stdout.
- Adapters gained `progress_note(line) -> str | None` (default `None`), so vendor stream formats stay behind the adapter boundary exactly as usage parsing does. `codex` implements it against the event shapes captured from a real run; the engine forwards notes **straight to the live listener, never to `orchestrator.jsonl`** — a note is ephemeral UI, and a long stage would otherwise bloat the durable log with hundreds. The renderer *updates the spinner text* rather than printing a line each time, so a ten-minute stage does not bury the run in scrollback.
- 🐛 **A real defect caught by my own test, not by review:** the first streaming implementation checked the deadline between lines, so a provider that hangs *while silent* would block in `for line in proc.stdout` and never time out — losing a timeout the buffered path has enforced since T34. The test sat for 30 s and returned `timed_out=False`. Replaced with a watchdog timer that kills the process at the deadline regardless of output.
- ✅ **Live-verified against real codex**: a note streamed while it worked — `$ /bin/zsh -lc "sed -n '1,240p' src/calc.py"` — which is exactly the intended shape (evidence of life and the rough shape of the work, not a transcript).
- **Honest limitation, recorded in the ADR:** only codex streams today. Moving `claude` to `--output-format stream-json` changes what its parser consumes, and that parser guards the Coder — the stage that edits files — so it is a separate step. Until then claude keeps the plain spinner, which is the degradation this ADR already requires of a non-streaming provider.
- **Untrusted-text handling is pinned by tests**, not just asserted in prose: notes cannot carry escape sequences, cannot smuggle Rich markup (`[red]` → `(red)`), are flattened to one line and truncated. A sink that raises cannot fail a stage.
- 🤖 The `Transport` protocol changed, so four test doubles implementing `run(invocation)` were updated to the new signature.
- ✅ **296 passed** (measured; +18 in `tests/unit/test_progress.py`), ruff clean.
- **All four queued ADRs (028–031) are now implemented.** Remaining from the older roadmap: tmux observability, new roles, a persistent REPL (ADR-026 alternative b), the repowise MCP interface, memory — plus claude streaming as ADR-030's follow-up.
